# Metric Factory 工作台使用指南

> 面向使用者的操作手册：浏览器里完成「行业模板 → 企业实例 → 微调与场景 → 审核导出」全流程，无需终端。启动方式见仓库根 [README](../README.md#web-工作台)（双击 `启动工作台.command`，或 `node dist/cli.js ui` 后打开 http://127.0.0.1:4173）。

## 0. 开始前

- 工作台只监听本机（127.0.0.1），数据不出本机；页面底部常驻边界声明「写操作仅限本地实例与映射文件」。
- 全程零客户端脚本：禁用 JavaScript 时所有功能照样可用（原生表单提交）。
- 所有写操作（改实例、存场景、批准审核）都经过同一套引擎校验——**校验不过零写盘**，错误会逐条列在页面上。

## 1. 创建实例（一分钟）

**首页 → 「开始问卷向导」**（或「先逛模板库」了解 7 个行业后再决定）。

向导三问：收入模式 / 用户结构 / 核心循环 → 系统匹配最合适的行业模板 → 命名生成实例。

生成后你得到：53–72 个带完整口径、维度、负责人与出处的行业指标，以及该行业的**种子分析场景**（如电商的「GMV 差距诊断」）。实例是一个 YAML 文件（默认存 `my-instance/instance.yaml`），git 可管、随时可改。

也可以在首页「打开已有实例」直接加载工作区扫描到的实例文件。

## 2. 模板库（了解你拿到了什么）

**侧栏 → 「模板库」**：7 个行业模板的完整指标字典表格（指标名/口径/维度/时间粒度/负责人/出处）。匹配不确定时，先在这里对比各行业的口径与指标构成。

## 3. 我的实例（主工作区）

打开实例后进入实例页，从上到下五块：

### 3.1 实例概览与导出

- 概览行：基模板版本、有效指标数、口径调整数、待审状态。
- **四个导出按钮**：MetricFlow YAML（进 dbt 语义层）/ Excel 字典（治理评审）/ Mermaid 指标树（汇报）/ SAP 语义包（JuanerAI 语义资产，YAML 含指纹与出处）。下载即文件落盘；导出前自动全量校验。
- 口径映射文件（`<实例名>.mapping.yaml`）存在时自动随 MetricFlow/SAP 导出生效。

### 3.2 fork diff（相对模板改了什么）

表格式列出：口径开关变化、字段修改、删除、新增——永远能回答「我们和行业模板的差异」。

### 3.3 指标树（杜邦式分解）

按模块分组（规模/质量/结构/效率/旅程）的树形视图，`× ÷` 徽标标注公式勾稽；北极星候选置顶。点击模块标题展开/收起。

### 3.4 微调实例（表单写回）

- **口径开关**：每个开关三个选项（不变/覆盖为开/覆盖为关），radio 原生控件。
- **删除指标**：每行一个指标名（对应 removed 段）。
- **新增指标**：JSON 数组，**必须含 provenance**（模板/人工/llm 出处）；与已有新增按名合并。
- **修改指标**：JSON 数组（name + 可选 display_name/definition/owner_role）。
- 点「校验并写回实例」→ 全量校验通过才写盘；失败则页面逐条列出 `[规则] 位置: 原因`，**实例文件零变化**。

> 移除已合入的 AI 新增指标：到审核中心「拒绝」，或直接编辑 YAML。

### 3.5 决策场景 · 分析体系（v5）

把「这个问题应该怎样分析」固化成配置。场景 = 决策用途 + 问题树 + 指标角色 + 方法引用 + 证据要求，随实例落盘并进入 SAP 语义包。

- **场景列表**：每场景一行（标题/用途摘要/指标角色统计），「来源」标记三态：`模板种子` / `实例新增` / `实例覆盖种子`。
- **新建/编辑**：结构化字段（id、标题、决策用途、方法引用、证据要求、输出、复盘规则）+ 两段逐行 DSL：
  - 问题树：`id|label|parent|metric`（4 槽竖线分隔，parent/metric 留空表示根或纯问题节点）
  - 指标角色：`metric|role|note`（role ∈ outcome | driver | guardrail）
- **规则**：决策用途必填（没有决策用途的场景不可保存）；树禁止成环/自指/悬空引用；**场景 id 创建后不可改**；v5 不提供删除入口（不需要的场景从 YAML 的 `added_scenarios` 移除）。
- **编辑模板种子** → 保存后成为「实例覆盖种子」（模板种子不动，实例加一条同 id 覆盖）。
- 保存失败：同页保留你的输入 + 逐行错误（含 DSL 行号），零写盘。

## 4. AI 草案（可选，v2）

1. **配置模型**：侧栏「设置」→ 填模型/密钥/网关（写入仓库根 `.env.local`，已 gitignore，页面打码不回显）。
2. **生成草案**：侧栏「AI 草案」→ 两种工坊——「描述业务，AI 出候选指标草案」或「一句话微调现有实例」→ 提交后进度页自动刷新。
3. **采纳**：完成后待采纳草案卡预览变更 → 填审核人 → 「采纳合入」（过引擎校验；AI 新增自动带 provenance + 待审标记）或「丢弃」。

**fail-closed**：AI 新增的指标未经人工审核前，导出被硬阻断（不是提示，是拒绝）。

## 5. 审核中心

列出所有待审的 LLM 指标（口径/出处/置信信息齐全）→ 逐条「批准」（填审核人，写 provenance.reviewed_by）或「拒绝」（移除）。批准后该指标即可导出。无待审时显示空状态与指引。

## 6. 状态与错误怎么看

| 你看到 | 含义 | 下一步 |
|---|---|---|
| chip「待审核 N」 | 有 N 个 LLM 指标未审核（导出被阻断） | 审核中心批准或拒绝 |
| chip「无待审」 | 全部已审核，可导出 | — |
| chip「模板种子/实例新增/实例覆盖种子」 | 场景来源 | — |
| 保存/写回失败 + 错误列表 | 校验未过，**零写盘**，你的输入还在 | 按错误逐条修正后重提交 |
| 端口自动换成 4174 | 4173 被占用（启动日志有说明） | 无需处理 |

## 7. 边界（设计如此，非缺陷）

- 单用户本地工具：无登录、无多人协同、无云端。
- 场景不可删除（v5）：不需要的场景编辑 YAML `added_scenarios` 段移除。
- 模板种子内容在模板文件里维护；实例里的覆盖不改模板。
- 升级代码后双击启动会自动重建（源码比构建产物新时）。
