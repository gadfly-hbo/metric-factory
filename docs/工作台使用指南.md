# Metric Factory 工作台使用指南

> 面向使用者的操作手册：浏览器里完成「描述业务问题 → AI 起草分析体系 → 修正微调 → 复核发布」全流程，无需终端。启动方式见仓库根 [README](../README.md#web-工作台)（双击 `启动工作台.command`，或 `node dist/cli.js ui` 后打开 http://127.0.0.1:4173）。

## 0. 开始前

- 工作台只监听本机（127.0.0.1），数据不出本机；页面底部常驻边界声明「写操作仅限本地实例、模板库（导入/另存方法）、映射文件与 releases/ 发布登记」。
- 全程零客户端脚本：禁用 JavaScript 时所有功能照样可用（原生表单提交）。
- 所有写操作（改实例、存场景、存蓝图、批准审核）都经过同一套引擎校验——**校验不过零写盘**，错误会逐条列在页面上。
- **写时宽、交付严**：工作稿允许带着缺口保存（边想边写）；但「检查与交付」视图的设计门会把缺口逐条列出，**缺口未清零且未完成业务复核前，导出与发布被阻断**。

## 1. 创建实例（三种起点，汇入同一工作台）

**推荐起点 · 首页「用一句话开始」**：用一句自然语言描述你的业务问题（例如「利润连续两个季度下滑，帮我搭一套经营诊断体系」）→ 提交后进入进度页（自动刷新）→ AI 生成**分析体系草稿**（蓝图 + 建议指标 + 建议场景）→ 预览页看清每项内容与影响 → 「采纳创建实例」或「放弃」。采纳后才落盘成实例；放弃则零改动。

> AI 草稿带未决项，需你修正与复核；它不编造业务事实。没有配置模型时也可走下方次要起点，全流程不受影响。

**次要起点**：

- **问卷向导**：「开始问卷向导」→ 回答收入模式 / 用户结构 / 核心循环 → 匹配行业模板 → 命名生成实例（53–72 个带完整口径、维度、负责人与出处的行业指标 + 种子分析场景）。
- **粘贴导入**：首页「粘贴导入」（或模板库页「导入模板」）→ 选择模板类型（**指标体系** / **分析方法**）→ 粘贴外部整理好的 YAML → 「解析预览」看清落盘位置与缺口标注 → 确认保存。目标已存在时拒绝覆盖（零写盘）。

生成后实例是一个 YAML 文件（默认存 `my-instance/instance.yaml`），git 可管、随时可改。首页「打开已有实例」可加载工作区扫描到的实例文件。

## 2. 模板库（了解你拿到了什么）

**侧栏 → 「模板库」**：

- **行业模板**：7 个行业模板的完整指标字典表格（指标名/口径/维度/时间粒度/负责人/出处）。
- **方法模板库**（模板库页入口，或实例「场景与方法」视图内嵌）：每个方法模板记录适用语境、输入角色（区分必需/可选）、步骤、证据要求与限制。内置三个：利润变动诊断、战略选项评估、关联与增量分析。方法「引用不实现」——场景绑定方法角色，执行由消费方负责。

## 3. 我的实例（四视图）

打开实例后，顶部四个页签：**01 体系总览 / 02 指标体系 / 03 场景与方法 / 04 检查与交付**。

### 3.1 体系总览（分析体系蓝图）

这里维护「这个业务问题应该怎样分析」的顶层结构（蓝图）：

- **蓝图卡片**：体系名称、起点意图（建设可复用体系 / 设计具体分析方案）、业务目的、研究问题或选择、范围边界、输出要求、适用语境（经营改善/战略选择/独立数据专题，可组合不分级）、调查组织方式（假设先行/深度研究/自主探索）。
- **问题结构**：问题树逐条列出，挂接的指标引用只读展示（指标定义唯一权威来源在指标体系视图，问题不重复定义）。
- **关键假设**：每条假设带支持证据 / 反对证据 / 改变判断的条件三要素；每条假设旁有**判断性质**（事实/解释/待验证假设/建议）与**核验状态**表单——判断越过证据不是写入错误，但会在交付视图呈现为缺口。
- **证据计划**：每条证据带类型/来源/核验办法/不足处置/状态（待获取/取得待核/已核验/支持不足/存在冲突）。**证据计划完整 ≠ 证据已取得**。
- **候选道路**：候选方案与取舍（战略选择类交付时要求至少两条）。
- **「一起完善」AI 助手卡**：输入修正指令（如「把候选道路补到三条」「证据计划加上竞争对手价格监测」）→ 生成建议预览（带出处：模型/prompt 版本/时间）→ **采纳才更新工作稿，放弃零改动**。
- **「编辑蓝图」**：进入蓝图编辑表单——上半部分结构化字段 + 五段逐行 DSL：
  - 问题结构：`id|标题|说明|指标引用（逗号分隔）`
  - 关键假设：`id|假设陈述|支持证据|反对证据|改变判断的条件`
  - 证据计划：`id|名称|类型|来源|核验办法|不足处置|状态（可省，默认 待获取）`
  - 候选道路：`id|候选道路|取舍`
- 没有蓝图时，总览提供「手工建立蓝图」入口；战略选择类允许**零指标**的纯定性设计。

> 保存蓝图经全量校验，失败零写盘；**相关修改会使已完成的业务复核失效**（需重新确认，见 3.4）。

### 3.2 指标体系（指标字典 + fork diff）

- **指标字典表**：有效指标全表（名称/口径/维度/时间粒度/负责人/出处），行内「删除…」入口——删除被引用的指标前**先展示影响页**（哪些问题、场景、方法绑定引用了它），确认才执行；无引用指标直接确认删除。
- **fork diff**：口径开关变化、字段修改、删除、新增——永远能回答「我们和行业模板的差异」。
- **指标树**：按模块分组的杜邦式分解树，`× ÷` 徽标标注公式勾稽；北极星候选置顶。
- **微调实例**：口径开关（不变/覆盖开/覆盖关）、删除指标、新增指标（JSON，必须含 provenance）、修改指标（JSON）→「校验并写回实例」全量校验通过才写盘。

> 导出与发布已移至「04 检查与交付」视图。

### 3.3 场景与方法（决策场景 + 方法绑定）

- **场景列表**：每场景一行（标题/用途摘要/指标角色统计），来源三态：`模板种子` / `实例新增` / `实例覆盖种子`；行内「另存方法」把该场景沉淀为可复用方法模板（写入 `templates/methods/`，角色从场景的指标角色派生：outcome/driver 为必需、guardrail 为可选；id 冲突拒绝覆盖）。
- **新建/编辑场景**：结构化字段（id、标题、决策用途、方法引用、证据要求、输出、复盘规则）+ 逐行 DSL：
  - 问题树：`id|label|parent|metric`（parent/metric 留空表示根或纯问题节点）
  - 指标角色：`metric|role|note`（role ∈ outcome | driver | guardrail）
  - **方法绑定**（可选）：`方法id@版本|角色|指标`——角色须为该方法已声明角色；写时只检查引用存在性，**语境适配与必需角色覆盖由交付门执法**（缺必需角色或语境不匹配会阻断交付，不阻断保存）。
- **分析方法库**：视图内嵌方法卡片（适用语境 chip + 角色 chip 区分必需/可选），「查看步骤、证据与限制」进详情页。
- 规则不变：决策用途必填；树禁止成环/自指/悬空引用；场景 id 创建后不可改；编辑模板种子保存为「实例覆盖种子」。

### 3.4 检查与交付（设计缺口 + 业务复核 + 导出发布）

- **设计缺口清单**：交付门全量检查逐条列出阻断项——业务目的缺失、假设缺三要素、证据缺三要素、方法语境不适配/必需角色未绑定、事实或解释未经核验（「已核验」证据为零或存在冲突证据）等。每条附位置与原因。
- **业务复核**：缺口为零后方可确认——填复核人 →「确认业务复核」。**复核绑定当前完整设计快照（内容指纹）**：之后任何相关修改（蓝图/场景/指标身份面）都使确认失效，状态变为「复核已失效 · 需重新确认」；查看和切换视图不影响确认。复核通过不代表结论成立、因果成立或经营效果已验证。
- **导出**：四个按钮（MetricFlow YAML / Excel 字典 / Mermaid 指标树 / SAP 语义包）——导出前自动全量校验（含设计门）；SAP 包内蓝图段剥离复核状态（复核是本地工作态，不随包携带）。
- **发布**：填版本号（semver）与可选变更说明 → 固定**不可变快照**并登记 `releases/index.yaml`。内容与既有发布完全相同（same-content）时**拒绝重复发版**——未修改不重复发版；同 `id@version` 重复发布同样拒绝。
- **回执**：JuanerAI 安装消费后的 adoption receipt 登记与对账（见 [sap-consumption-guide](./sap-consumption-guide.md)）。

## 4. AI 草案（可选，v2）

1. **配置模型**：侧栏「设置」→ 填模型/密钥/网关（写入仓库根 `.env.local`，已 gitignore，页面打码不回显）；本机已有 pi CLI 凭据时零配置自动发现。
2. **两条 AI 通路**：
   - **体系总览「一起完善」**：修正当前蓝图与实例（建议预览 → 采纳/放弃）。
   - **侧栏「AI 草案」**：指标级工坊——「描述业务，AI 出候选指标草案」或「一句话微调现有实例」。
3. **采纳**：完成后预览变更 → 填审核人 →「采纳合入」（过引擎校验；AI 新增自动带 provenance + 待审标记）或「丢弃」。

**fail-closed**：AI 新增的指标未经人工审核前，导出被硬阻断（不是提示，是拒绝）。

## 5. 审核中心

列出所有待审的 LLM 指标（口径/出处/置信信息齐全）→ 逐条「批准」（填审核人，写 provenance.reviewed_by）或「拒绝」（移除）。批准后该指标即可导出。无待审时显示空状态与指引。

## 6. 状态与错误怎么看

| 你看到 | 含义 | 下一步 |
|---|---|---|
| chip「待审核 N」 | 有 N 个 LLM 指标未审核（导出被阻断） | 审核中心批准或拒绝 |
| chip「无待审」 | 全部已审核，可导出 | — |
| chip「已复核 · 有效」 | 业务复核确认且设计快照未变 | 可固定设计版本 |
| chip「复核已失效 · 需重新确认」 | 复核后设计被修改 | 检查与交付视图重新确认 |
| chip「未复核」 | 尚未完成业务复核 | 缺口清零后到检查与交付确认 |
| chip「模板种子/实例新增/实例覆盖种子」 | 场景来源 | — |
| 「设计未就绪」+ 缺口清单 | 交付门存在阻断项 | 按清单逐条处理后复核 |
| 保存/写回失败 + 错误列表 | 校验未过，**零写盘**，你的输入还在 | 按错误逐条修正后重提交 |
| 发布失败「same-content」 | 内容与既有发布完全相同 | 无需发版；有变更再升级版本号 |
| 端口自动换成 4174 | 4173 被占用（启动日志有说明） | 无需处理 |

## 7. 边界（设计如此，非缺陷）

- 单用户本地工具：无登录、无多人协同、无云端。
- 场景不可删除（v5）：不需要的场景编辑 YAML `added_scenarios` 段移除。
- 模板种子内容在模板文件里维护；实例里的覆盖不改模板；导入与另存方法拒绝覆盖既有模板文件。
- 蓝图的可选性：实例可以没有蓝图（纯指标体系交付），蓝图也可以零指标（纯定性设计）；两者互不强制。
- AI 助手只出建议：采纳才进工作稿，LLM 内容未经复核不可交付。
- 升级代码后双击启动会自动重建（源码比构建产物新时）。
